# Robot Rental WebSocket Server

A secure WebSocket server for real-time robot control with Ed25519 authentication.

## Overview

This server implements **Mode 2: Robot Rental** - allowing users to rent and control robots in real-time after paying with TREAT tokens on the Sui blockchain.

### Architecture

```
┌─────────────────────────────────────────────────────────────────────┐
│                     RENTAL SESSION FLOW                             │
│                                                                     │
│   1. USER CREATES SESSION (dApp)                                    │
│      └─> Deposits TREAT tokens as escrow                            │
│      └─> Registers Ed25519 public key for command signing           │
│      └─> Session object created on blockchain                       │
│                                                                     │
│   2. USER CONNECTS TO WEBSOCKET                                     │
│      └─> Sends session ID for authentication                        │
│      └─> Server verifies session exists on-chain                    │
│      └─> Server checks session is active and not expired            │
│                                                                     │
│   3. USER SENDS SIGNED COMMANDS                                     │
│      └─> Each command signed with user's Ed25519 private key        │
│      └─> Server verifies signature against on-chain public key      │
│      └─> Sequence numbers prevent replay attacks                    │
│      └─> Robot executes the command                                 │
│                                                                     │
│   4. SESSION ENDS (dApp)                                            │
│      └─> User or operator ends session on-chain                     │
│      └─> Operator receives payment for used time                    │
│      └─> User receives refund for unused time                       │
│      └─> Server disconnects client                                  │
└─────────────────────────────────────────────────────────────────────┘
```

### Security Model

| Layer                  | Protection                                              |
| ---------------------- | ------------------------------------------------------- |
| **Session Binding**    | Server verifies session exists on blockchain            |
| **Command Auth**       | Ed25519 signatures verified against on-chain public key |
| **Replay Protection**  | Sequence numbers must increment for each command        |
| **Timeout Protection** | Sessions expire after prepaid time runs out             |
| **Tunnel Security**    | Cloudflare tunnel provides HTTPS/WSS encryption         |

## Quick Start

### 1. Install Dependencies

```bash
cd server
pnpm install
```

### 2. Configure Environment

The `.env` file is auto-generated by the publish script:

```bash
cd ../publish
./publish.sh
```

Or copy the example and configure manually:

```bash
cp .env.example .env
# Edit .env with your contract addresses
```

### 3. Build & Run

```bash
# Build TypeScript
pnpm build

# Start server
pnpm start

# Or use development mode (auto-reload)
pnpm dev
```

### 4. (Optional) Start Tunnel for Public Access

```bash
# Install cloudflared (first time only)
./scripts/install-cloudflared.sh

# Start tunnel
./scripts/start-tunnel.sh
# Output: https://random-words.trycloudflare.com
```

Or start both server and tunnel together:

```bash
./scripts/start-all.sh
```

## WebSocket Protocol

### Client → Server Messages

#### 1. Authentication

```json
{
  "type": "auth",
  "sessionId": "0x..."
}
```

**Response:**

```json
{
  "type": "auth_response",
  "success": true,
  "session": {
    "robotName": "Bittle-1",
    "prepaidMinutes": 10,
    "remainingMinutes": 9,
    "sequenceNumber": 0
  }
}
```

#### 2. Robot Command (must be authenticated)

```json
{
  "type": "command",
  "action": "wave",
  "sequence": 1,
  "signature": "hex-encoded-ed25519-signature",
  "timestamp": 1699999999999
}
```

**Signature Format:**
The signature must be over the message:

```
session_id (32 bytes) || sequence_number (8 bytes, big-endian) || action (UTF-8)
```

**Response:**

```json
{
  "type": "ack",
  "action": "wave",
  "sequence": 1,
  "success": true
}
```

#### 3. Ping (keep-alive)

```json
{
  "type": "ping"
}
```

**Response:**

```json
{
  "type": "pong",
  "serverTime": 1699999999999
}
```

#### 4. Status Request

```json
{
  "type": "status"
}
```

**Response:**

```json
{
  "type": "status_response",
  "session": {
    "robotName": "Bittle-1",
    "prepaidMinutes": 10,
    "remainingMinutes": 7,
    "elapsedMinutes": 3,
    "sequenceNumber": 5,
    "isActive": true
  }
}
```

### Server → Client Messages

#### Error

```json
{
  "type": "error",
  "code": "INVALID_SIGNATURE",
  "message": "Signature verification failed"
}
```

#### Session Ended

```json
{
  "type": "session_ended",
  "reason": "Session time expired"
}
```

### Error Codes

| Code                | Description                               |
| ------------------- | ----------------------------------------- |
| `INVALID_MESSAGE`   | Malformed JSON or unknown message type    |
| `NOT_AUTHENTICATED` | Must authenticate before sending commands |
| `SESSION_NOT_FOUND` | Session ID doesn't exist on blockchain    |
| `SESSION_EXPIRED`   | Prepaid time has run out                  |
| `INVALID_SIGNATURE` | Ed25519 signature verification failed     |
| `INVALID_SEQUENCE`  | Sequence number doesn't match expected    |
| `INVALID_ACTION`    | Action not in supported list              |
| `ROBOT_BUSY`        | Robot is executing another command        |
| `INTERNAL_ERROR`    | Server error                              |

## Client Implementation Example (JavaScript)

```javascript
import * as ed25519 from "@noble/ed25519";

class RobotClient {
  constructor(wsUrl, sessionId, privateKey) {
    this.wsUrl = wsUrl;
    this.sessionId = sessionId;
    this.privateKey = privateKey;
    this.sequence = 0;
  }

  async connect() {
    this.ws = new WebSocket(this.wsUrl);

    this.ws.onopen = () => {
      // Authenticate with session ID
      this.ws.send(
        JSON.stringify({
          type: "auth",
          sessionId: this.sessionId,
        }),
      );
    };

    this.ws.onmessage = (event) => {
      const msg = JSON.parse(event.data);

      if (msg.type === "auth_response" && msg.success) {
        this.sequence = msg.session.sequenceNumber;
        console.log("Authenticated!");
      }
    };
  }

  async sendCommand(action) {
    const nextSequence = this.sequence + 1;

    // Build message to sign
    const message = this.buildMessage(nextSequence, action);

    // Sign with Ed25519
    const signature = await ed25519.signAsync(message, this.privateKey);

    // Send command
    this.ws.send(
      JSON.stringify({
        type: "command",
        action,
        sequence: nextSequence,
        signature: bytesToHex(signature),
        timestamp: Date.now(),
      }),
    );

    this.sequence = nextSequence;
  }

  buildMessage(sequence, action) {
    // session_id (32 bytes) || sequence (8 bytes BE) || action (UTF-8)
    const sessionBytes = hexToBytes(this.sessionId);
    const seqBytes = new Uint8Array(8);
    let seq = BigInt(sequence);
    for (let i = 7; i >= 0; i--) {
      seqBytes[i] = Number(seq & 0xffn);
      seq >>= 8n;
    }
    const actionBytes = new TextEncoder().encode(action);

    const msg = new Uint8Array(sessionBytes.length + 8 + actionBytes.length);
    msg.set(sessionBytes, 0);
    msg.set(seqBytes, sessionBytes.length);
    msg.set(actionBytes, sessionBytes.length + 8);
    return msg;
  }
}
```

## Cloudflare Tunnel

### Why Use a Tunnel?

- **NAT Bypass**: Access server from anywhere without port forwarding
- **No Static IP**: Works with dynamic home IP addresses
- **HTTPS/WSS**: Automatic SSL certificate
- **DDoS Protection**: Cloudflare's edge network
- **IP Hiding**: Your home IP is not exposed

### Quick Tunnel (No Account)

```bash
./scripts/start-tunnel.sh 8080
```

This creates a temporary public URL like:

```
https://cavity-bright-apache.trycloudflare.com
```

Clients connect via:

```
wss://cavity-bright-apache.trycloudflare.com
```

### Production Tunnel (Persistent URL)

For production, create a named tunnel with a Cloudflare account:

```bash
# Login
cloudflared tunnel login

# Create tunnel
cloudflared tunnel create robot-rental

# Configure tunnel
cat > ~/.cloudflared/config.yml << EOF
tunnel: robot-rental
credentials-file: ~/.cloudflared/<tunnel-id>.json
ingress:
  - hostname: robot.yourdomain.com
    service: http://localhost:8080
  - service: http_status:404
EOF

# Start tunnel
cloudflared tunnel run robot-rental
```

## SDK Client Note

The server and CLI use `SuiGraphQLClient` (`@mysten/sui/graphql`) while the dApp uses `SuiGrpcClient` (`@mysten/sui/grpc`), which is required by `@mysten/dapp-kit-react`. These clients may return object fields in slightly different formats (e.g., `vector<u8>` serialization). The server's `hexToBytes()` handles multiple formats (hex, number arrays, base64) to accommodate this.

### Testing Without Hardware

Set `SIMULATE_ROBOT=true` in `.env` to run without a physical robot.
Commands will be logged with their expected duration.

### Connecting Physical Robot

1. Connect Petoi Bittle via USB
2. Find serial port: `ls /dev/cu.* /dev/ttyACM*`
3. Update `.env`:
   ```
   SIMULATE_ROBOT=false
   SERIAL_PORT=/dev/cu.usbmodem14101
   ```
